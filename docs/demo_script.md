# Demo 录屏脚本（5 分钟）

演示家庭：Lim 家三个孩子（`vaccinepath/data/mock_family.json`）
- **Mei** 20 个月：本地出生、按时打到 15 个月，**18 个月加强针漏了**，年度流感到期 → 展示逾期提醒 + 人工确认补种时间
- **Kai** 3 岁 3 个月：全部按时 → 展示"没事就不打扰"
- **Priya** 2 岁 3 个月：2026-08 从印度迁入，接种卡大部分都打了（含 9 个月的 MR），**缺 18 个月加强针**，7 条记录待核实 → 展示海外记录对照 NCIS + 人工核实

录屏前：`scripts/gateway.sh start && scripts/agent_setup.sh --reset && scripts/ui.sh`，浏览器开 http://localhost:8501。

| 时间 | 页面 | 动作 | 说的话 | 覆盖的验收要素 |
|---|---|---|---|---|
| 0:00 | 档案 | 滚到 Priya，指出 7 条 `overseas_unverified` + 1 条 `earlier_than_schedule`（9 个月 MR） | "规则引擎把印度接种卡逐条对到 NCIS：抗原对上了，但 9 个月的 MR 早于 NCIS 的 12 个月，这不是我们能判的，标给医生。" | 工具调用、安全响应 |
| 0:40 | 接种时间线 | 选 Priya：4 剂逾期，每行有依据与 NCIS 页码；选 Kai：全绿 | "每一剂的到期/逾期都是确定性规则算的，来源是 MOH 2026-04 的表，不是模型猜的。" | 工具调用、日志可追溯 |
| 1:10 | 侧栏 | 点 **⏩ 快进到下一次检查**，等 ~20s，读摘要 | "agent 平时按 cron 每天 9 点自己醒；这个按钮就是手动触发同一条路径。它醒来后：读状态 → 调规则引擎 → 建任务、发提醒、转人工 → 记日志 → 睡。" | **目标驱动、多步规划、工具调用、记忆/状态** |
| 1:50 | 待办与提醒 | 选 Mei：4 张任务卡；展开一张做**接种前安全筛查**，把"当前正在生病"选"是"，提交 → 黄色提示"已转医生审核" | "任何非'否'的回答都不由系统判断能不能打，直接进人工审核。" | **人工监督、安全响应** |

| 3:40 | 侧栏 | 再点 **快进**，读摘要：它说出"Mei 流感已完成、新增 URGENT 打卡；Priya 记录已核实、审核已完成；已再次提醒未回应的任务；与上次相比…" | "第二次醒来它知道上次做了什么、家长和医生这期间做了什么，没有重复建任务、没有重复审核，未回应的提醒会重发、三次后升级。" | **记忆/状态、多步规划** |

## 7 条验收要素 → 证据位置

| 要素 | 证据 |
|---|---|
| 目标驱动 | thread goal（`vaccinepath/agent/prompts.py: GOAL_OBJECTIVE`）：单次唤醒完成条件；摘要末尾"等待人工 / 等待家长" |
| 多步规划 | 唤醒 prompt 的 Perceive→Reason→Act→Record 流程；日志页"agent 唤醒记录"里每轮 14–18 次有序工具调用 |
| 工具调用 | 13 个 `vp_*` 工具（`vaccinepath/tools.py`），经 `config.yaml` 挂进 DeerFlow；规则引擎 4 函数 |
| 记忆/状态 | `reuse_thread` 定时任务 + `data/db.json`；第二次唤醒的摘要引用上次动作、幂等不重复 |
| 人工监督 | 人工审核页：筛查非"否"、逾期补种、海外记录、URGENT/WARN 打卡全部进队列；医生决定写 `human_decision` |
| 安全响应 | 打卡 URGENT 红框 + 转审；筛查不判适宜性；固定免责语；原则 §0"PDF 没写不猜" |
| 日志可追溯 | 审计日志每条：actor / 动作 / 输入 / 输出 / 来源页码 / 人工决定 |

## 备用：不依赖前端的证据
`scripts/phase2_demo.sh` 一键输出两次唤醒的工具调用与 `db.json` 统计（任务数、提醒次数、审核理由数、打卡判定、日志分布）。
