# Demo 录屏脚本

全程录，后期剪到 3 分钟。下面每步写清：**点哪 / 看什么 / 旁白一句话**。

## 录之前

```bash
scripts/gateway.sh start          # 后端
scripts/agent_setup.sh --reset    # 数据回到 mock 家庭 + 重建 agent（唤醒计数 0）
scripts/ui.sh                     # 前端 http://localhost:8501
```

浏览器停在「档案」页，窗口 1400px 以上，侧栏显示「🟢 gateway 在线 · agent 已建」。

演示家庭 Lim 家三个孩子：
- **Mei** 20 个月 — 本地出生、按时打到 15 个月，18 个月加强针漏了，年度流感到期
- **Kai** 3 岁 3 个月 — 全部按时，用来对照"没事就不打扰"
- **Priya** 2 岁 3 个月 — 2026-08 从印度迁入，接种卡大部分已打（含 9 个月的 MR），缺 18 个月加强针，7 条记录待核实

---

## 1. 档案：看 Priya 的海外记录

**点哪**：「档案」页，滚到最下面的 Priya 卡片。
**看什么**：她的 7 条印度记录表格；表格下面一排校验结果——7 条 `🩺 需人工确认 overseas_unverified`，外加 1 条 `earlier_than_schedule`（2025-03-03 的 MR 在 9 月龄接种，早于 NCIS 推荐的 12 个月）。
**旁白**：「规则引擎把印度接种卡逐条对到新加坡 NCIS：抗原对得上，但 9 个月打的麻疹针早于本地推荐月龄，这不是系统能判的，标给医生。」

## 2. 侧栏：快进到下一次检查

**点哪**：侧栏红色按钮「⏩ 快进到下一次检查」，等 20–40 秒。
**看什么**：按钮上方转圈 →「完成：success，Ns，18 次工具调用」；下面展开「上次唤醒摘要」，逐条读它写的：Mei 3 剂逾期 + 流感到期、Kai 无事不打扰、Priya 7 条待核实 + 4 剂逾期、各自转了几项人工审核。侧栏出现「已唤醒 1 次」。
**旁白**：「agent 平时按 cron 每天早上 9 点自己醒；这个按钮就是手动触发同一条路径。它醒来后读状态、调规则引擎、建任务、发提醒、把要医生拍板的转人工，然后记日志再睡。」

## 3. 待办：做一次接种前筛查

**点哪**：「待办与提醒」页 → 孩子选「Mei」→ 第一张卡「Mei DTaP B1 逾期补种」→ 展开「接种前安全筛查」→ 把第 3 题「当前正在生病？」点成「是」→「提交筛查」。
**看什么**：页面顶部黄色提示「⚠️ Mei 的接种前筛查已提交：有标记项，已转医生审核，请等待审核结果再预约」；展开框里回显「已筛查…标记项：当前正在生病＝是」。
**旁白**：「任何一个非'否'的回答，系统都不判断这孩子能不能打，直接进人工审核队列——这是硬规则。」

## 4. 待办：标记 Mei 的流感已接种

**点哪**：同一页往下，「Mei INF annual 应接种」卡 → 展开「标记已接种」→「确认」。
**看什么**：绿色提示「✅ 已记录 Mei 于今天接种 INF。接种后请到「接种后打卡」页填写观察情况。」任务状态变「已完成」。
**旁白**：「家长回应了，任务关闭，接种记录同时写进档案。」

## 5. 打卡：41.5°C + 抽搐

**点哪**：「接种后打卡」页 → 孩子选「Mei」→ 默认已指向刚打的那针（显示"接种后第 0 天"）→ 勾「量了体温」，体温填 `41.5`，部位选「耳温」→「急诊指征」里勾「抽搐」→「提交打卡」。
**看什么**：红框「**请立即前往儿童急诊**」+「触发项：急诊指征：抽搐；体温超过急诊阈值：41.5°C > 41.0°C」+ 引用的官方原句「Has a fit (seizure or convulsion)」「Has a temperature of more than 41.0°C…」+「已自动转入「人工审核」队列」+ 依据行（HealthHub，2026-06-17 复审）。
**旁白**：「升级判定由规则引擎按 HealthHub 和 KKH 的官方判据做，LLM 不参与；红框下面这两句是从官方页面原文里检索出来的，不是模型自己写的。」

## 6. 人工审核：批准 Priya

**点哪**：「人工审核」页。
**看什么**：先看队列顺序——Mei 的单子置顶，标题带 🚨「有 URGENT 打卡」，卡片里第一条就是红色的 URGENT 打卡（后面跟着 agent 引用的官方原句），下面才是筛查标记和逾期确认；重复的筛查条目被合并成一条。
**再点**：Priya 的单子 → 待核实记录里勾选几条 → 审核意见写「已核对印度接种卡；9 个月 MR 不计入 MMR 剂次；18 月加强针安排 2026-10-05」→「✅ 批准」。
**看什么**：绿色提示「✅ Priya 的审核单已批准；仍有 N 条记录未核实，agent 下次唤醒会继续提示」。
**旁白**：「医生在这里拍板：核实哪几条记录、补种日期定在哪天。每个决定都写进日志的人工决定列。」

## 7. 侧栏：再快进一次

**点哪**：侧栏「⏩ 快进到下一次检查」，等 20–40 秒。
**看什么**：新摘要里它说出这期间发生的事——Mei 的流感已完成、新增了 URGENT 打卡并已转急诊提醒、Priya 的记录已核实且引用医生给的补种日期、未回应的提醒已重发（第 2 次）、没有重复建任务。侧栏「已唤醒 2 次」。
**旁白**：「第二次醒来，它知道上次做了什么、家长和医生这期间做了什么。没有重复建任务，未回应的提醒会重发，三次之后升级为'家长多次未响应'再转人工。」

## 8. 日志：全程可追溯

**点哪**：「日志」页 →「审计日志」标签，actor 里勾 `rule_engine` 看规则判定，勾 `clinician` 看刚才那条审核决定（人工决定列＝approved）；找 `retrieve_guidance` 那几行，输出列是 `retrieved: healthhub_fever_in_children.md`。
**再点**：「agent 唤醒记录」标签 → 选一次 run → 看这一轮 18 次工具调用的完整清单和摘要。
**旁白**：「每一步是谁做的、输入什么、依据哪一份文件的哪一页、医生怎么决定，全部可追溯——包括 agent 引用了哪份官方指引。」

## 9. 收尾一句

**旁白**：「不诊断、不替代医生。判定全在确定性规则引擎，LLM 只负责编排流程和写给人看的文案；官方文件里没写的，一律转人工审核。」

## 7 条验收要素 → 片中证据

| 要素 | 出现在第几步 | 证据 |
|---|---|---|
| 目标驱动 | 2、7 | thread goal 定义单次巡检的完成条件；摘要末尾恒有"等待人工 / 等待家长" |
| 多步规划 | 2、7、8 | Perceive→Reason→Act→Record；唤醒记录里每轮 17–20 次有序工具调用 |
| 工具调用 | 2、5、8 | 14 个 `vp_*` 工具（含 `vp_get_guidance`），经 `config.yaml` 挂进 DeerFlow |
| 记忆 / 状态 | 7 | `reuse_thread` 定时任务 + `data/db.json`；第二次摘要引用上次动作、幂等不重复建 |
| 人工监督 | 3、6 | 筛查非"否"、逾期补种、海外记录、URGENT 打卡全部进队列；医生决定写 `human_decision` |
| 安全响应 | 5、9 | URGENT 红框 + 自动转审；不判接种适宜性；固定免责语；语料未覆盖就不引用 |
| 日志可追溯 | 8 | 每条含 actor / 动作 / 输入 / 输出 / 来源页码 / 人工决定；`retrieved:` 行记录引用来源 |

## 备用（不依赖前端）

`scripts/phase2_demo.sh` 一键跑完两次唤醒并打印 `db.json` 统计，可作为录屏失败时的兜底证据。
